You are coding a single case from the Delhi High Court commercial docket for an empirical legal-research dataset. You do TWO things, at the CASE level, for the whole case (not per order):
  (1) decide whether this is an intellectual-property (IP) dispute at all, and
  (2) if it is, identify which IP rights the plaintiff actually ASSERTS.
You output ONE JSON object. Do NOT assume the case is an IP case — decide it from the evidence in the orders.

You receive all orders of one case in chronological order, separated by `=== ORDER N ===` headers (each with order_filename and order_date). Output valid JSON and nothing else.

==============================================================
STEP 1 — IS THIS AN IP CASE?  (decide first; do not assume)
==============================================================

Read the orders and classify ip_status as exactly one of "yes", "no", "unclear".

- "yes" — there is AFFIRMATIVE evidence this is an IP dispute. Any ONE suffices:
    * a claim, prayer, or judicial finding on an IP right (infringement of a trade mark / copyright / patent / design / GI; passing off; personality rights; trade-secret / confidential-information / source-code misappropriation), OR
    * unambiguous IP-suit markers: "registered trade mark", registration numbers for the plaintiff's suing mark, "infringement", "deceptively similar", a Local Commissioner appointed to seize infringing goods, John Doe / dynamic injunction / website-blocking relief, or linkage to an IP-Division matter (e.g. "C.O.(COMM.IPD-TM)", "IPD-PAT", "IPD-CR").

- "no" — there is AFFIRMATIVE evidence it is NOT an IP dispute: the suit is plainly something else (recovery of money / contract, defamation, oppression-mismanagement, arbitration, tenancy, a pure commercial claim) and no IP right is in issue anywhere in the orders.

- "unclear" — you cannot tell from the supplied orders. Typically every supplied order is procedural (summons, exemptions, condonation, pleadings management, mediation, adjournments) and NONE states the plaint's subject, any prayer, or any finding. Do NOT default to "yes" because the suit is a CS(COMM) number or because of the parties' industry — absence of the plaint/opening order means "unclear", not "yes".

Put a short verbatim quote (or a one-line reason for "no"/"unclear") in ip_evidence.

If ip_status is "no" or "unclear": set rights_asserted = [], rights_evidence = {}, and STOP — do not code rights. Only proceed to Step 2 when ip_status = "yes".

==============================================================
STEP 2 — WHICH RIGHTS ARE ASSERTED?  (only if ip_status = "yes")
==============================================================

A right is ASSERTED only when the text shows (1) the plaintiff SEEKS A REMEDY on that basis, OR (2) the court makes a FINDING on it. A right is NOT asserted when the text only describes what the plaintiff OWNS (portfolio recital), or uses a word in passing. Owning a copyright registration is not a copyright claim; "patent-filed software" is not a patent claim. If you cannot quote a prayer or a finding, do not code the flag.

Anchor on the FIRST SUBSTANTIVE ORDER (the one that sets out the plaint / prayers / dispute). Combine early orders if needed. rights_asserted is one case-level array.

CLOSED LIST — per-flag test (code true only if you can answer YES and quote it):
- "trademark" — relief for / finding of infringement of a REGISTERED mark. Look for "registered trade mark/mark", registration no. of the suing mark. Trade dress/packaging/shape = trademark ONLY if asserted registered.
- "passing_off" — passing off pleaded or found; OR (where registration is not stated) relief on goodwill/reputation/deception/get-up/prior-user grounds. Captures all common-law misrepresentation incl. unregistered marks, trade dress, get-up, unregistered designs framed as passing off, character merchandising, domain/website impersonation.
- "copyright" — relief for / finding of copyright INFRINGEMENT (artistic/literary/software work). Owning a copyright registration is NOT enough.
- "patent" — relief for / finding of patent infringement, or the Patents Act as the basis. "patent-filed" descriptors do not count.
- "designs" — REGISTERED-design infringement (Designs Act). Unregistered designs framed as passing off = passing_off.
- "GI" — geographical-indication claim (GI Act, s.16/22).
- "personality_rights" — publicity / personality-rights claim (name, image, voice, likeness).
- "other_ip" — trade secrets, confidential information, source-code misappropriation, plant varieties, semiconductor layouts.

TRADEMARK vs PASSING_OFF (registration decides):
- Registered mark, infringement only → trademark true, passing_off FALSE.
- Registered mark AND passing off pleaded together → BOTH true (modal Delhi HC pattern; do not drop the passing_off limb).
- Unregistered mark / trade dress, passing off → trademark FALSE, passing_off true.
- Registration not stated → passing_off true if the language fits; trademark only if registration is affirmatively indicated.
- Plaintiff owns a registration but sues only on common-law rights → passing_off true; trademark only if a registered-mark infringement claim is actually made.
